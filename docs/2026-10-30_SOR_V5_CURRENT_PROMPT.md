## 2026-11-11 기능축소 작업연계 — 최우선 상태와 승인 범위

### 확정 방향·보존 범위·미결정
- **사용자 확정 방향:** 독립 마킹 ON/OFF는 기간선택으로 대체한다. 선택 완료 시 선택 구간의 BUY/SELL·결과표·평단·손익·승인된 가상청산을 표시하고, 선택 해제 시 가상 결과·표식만 지우며 캔들·지표·필터 표시를 보존한다. 독립 마킹 버튼 제거가 모든 마커·가상매매 계산 삭제를 뜻하지 않는다.
- **후속 축소 단계:** 2순위는 '정규장만 표시' 옵션, 3순위는 **V5 전용 실시간 틱 소비·차트 갱신** 분리다. 순서는 승인됐지만 기본 표시 범위와 CURRENT 처리 결정은 남아 있으므로 1순위 구현 중 이 두 기능을 임의 변경하지 않는다.
- **절대 보존:** 실매매의 틱 수신과 틱 기반 매수·매도/가격 판단, 공용 시세 host·주문·모의검증·간이차트, 13개 직접 기준봉·기존 원천/세션/웜업 규칙. V5 결과를 실주문·계좌·실매매 상태에 전파하지 않는다.
- **미결정 1 — 기본 표시 범위:** 정규장 옵션 제거 후 기존 OFF의 '증빙이 유효한 허용 전체장'을 고정 기본값으로 쓰는 안은 제안이다. 승인 전 ON/OFF 설정·계산 의미를 임의 변경하지 않는다.
- **미결정 2 — 당일 CURRENT:** 틱 갱신 제외 이후 조회 시점 부분봉의 표시·계산 포함·유효성 기준은 아직 확정되지 않았다. 틱 제외만으로 CURRENT 삭제·완성봉 전용·만료 검사 우회를 결정하지 않는다.

### 수신봉 처리 방침 — 승인된 1순위 적용 기준
- 키움 서버의 해당 기준봉 직접봉을 기본 원천으로 신뢰한다. 무오류를 보장한다는 뜻은 아니며, 서버 OHLCV를 과거 M1 재구성 등으로 다시 만들어 진위를 증명하지 않는다.
- 입고 시 요청/종목/시장/기준봉 대응, 필수값·시간·숫자 형식과 정규화 후 명백한 OHLCV 모순을 확인한다. 거래량 0이나 시간 공백만으로 누락·오류를 단정하지 않는다.
- 유효한 원천 수신 증빙과 동일한 불변 데이터 버전이 확인된 재사용에서는 기존 검증 결과를 사용한다. 같은 객체라는 이유만으로 불변을 인정하지 않으며, 요청 세대·취소·데이터/설정 변경 및 결과 적용 대상의 일관성은 계속 보호한다. 동일 봉 전체와 현재 host 증빙의 반복 전수 대조를 무조건 요구하지 않는다.
- 봉수 부족·누락과 값 오류를 구분한다. 확보한 정상 범위를 보존하고 필터별 준비 구간만 평가한다. 명백한 이상은 해당 봉 및 그 봉에 의존하는 지표·신호·손익 계산에 한정하여 보류하고, 무관한 정상 범위까지 차단하지 않는다.
- 현재 host 관측이 `None`이라는 사실만으로 기존 OHLCV를 오류로 판정하거나 정상으로 승인하지 않는다. 유효한 기존 수신 증빙·동일 입력·유효 요청이 확인되면 그 자료를 재사용한다. 확인되지 않으면 기존 정상 차트 보존과 새 계산/결과 반영 보류를 구분하며 가짜 증빙·무조건 통과는 금지한다.
- 필요 시 같은 원천·같은 기준봉의 기존 직접조회 경로로 재확인한다. 기존 전체 목표 수량 네이티브 요청·캐시 재사용 조건과 TR 제한을 유지하고, 부분 조회 증빙을 전체 이력에 붙이거나 자동 무한 재조회·`_NX` 우회·가상봉 보충을 하지 않는다.
- 실제 형성봉 값 변경·수정주가·시장 기준 변경은 동일 데이터 재사용과 구별한다. 이 방침만으로 CURRENT의 표시·계산 포함·만료 정책이나 실매매/모의검증/간이차트의 안전 규칙을 변경하지 않는다.

- 변경은 복원 가능한 단위로 수행한다. 현행 문서에는 최종 유효 계약만 남기고, 대체된 내용은 중앙 계약 이력 문서로 분리한다.

- 이미 확정한 기준봉·원천·조회량·필터·UI 계약을 작업 기준선으로 고정한다. 실제 결함 근거 없이 전 기준봉 수량을 다시 올리거나 새 설계를 끼워 넣지 않는다.
- 수정 제안 전 **재현된 증상, 코드·수신 근거로 확인한 원인, 정확한 수정 위치·범위, 실매매 공용엔진 영향, 유지할 기존 기능, 복원점, 필수 확인 기준**을 정리한다. 근거 없는 수량 확대·막연한 권장을 승인 요청으로 포장하지 않는다.
- GPT+DC는 비코드 총괄·문서·복원·보고만 수행한다. 프로그램 코드·오류 원인 분석은 Codex CLI Astra, 구현·수정은 Codex Sol, 계약 조사·적용과 방향 감사는 웹앱 Terra의 전담이다. 사용자에게 승인되지 않은 정책 변경을 강요하거나 기존 계약을 추정으로 무력화하지 않는다.
- 중요 설계 변경이나 실매매 공용엔진 영향은 **아스트라 독립 감사**를 거친다. 같은 파일은 지정된 단일 담당자만 수정하며 감사역은 읽기 전용이다. 사용자 승인 없는 코드·설정·테스트 기대값 변경, 기능 폐기, 자료 정리는 금지한다.
- 구현 중심으로 진행하며 해당 변경에 직접 필요한 검증만 수행한다. 단 **검증 최소화는 필수 실제 기능 확인의 생략이 아니다.** 오프라인 테스트·격리 환경 PASS를 실제 GUI 정상화 또는 실매매 운영 완료로 확대 보고하지 않는다.
- 단위 수정 성공과 **V5 전체 완료**를 구별한다. 전체 완료는 최우선 작업연계에서 사용자 승인으로 확정한 기능 범위의 13개 기준봉 로딩·지표 필터·기간선택 결과·전환·재진입 등이 실제 정상 동작함을 확인한 뒤 선언한다. 미승인 축소를 완료 범위 축소로 선반영하거나, 미확인·자료 부족·기존 별도 실패(시세원천 관련 3건)를 해결된 것으로 처리하지 않는다.

## 지원 기준봉과 원천

### 용어와 최우선 원천 선택 계약

- **SOR는 최선주문집행을 위한 주문 라우팅**이다. 차트의 **통합시세(KRX+NXT)** 와 개념을 구분한다. 프로그램의 기존 `SOR` 원천 표기는 검증된 키움 **통합시세 `_AL`** 요청 경로를 뜻하며, 실주문 집행 결과·주문거래소를 뜻하지 않는다.
- 시세 원천 표기: `_AL`=프로그램이 요청하는 키움 통합시세, `_NX`=NXT 단독시세, 접미사 없는 6자리=KRX 전용 경로. 실제 수신·적격성·세션·기준봉 증거를 각각 확인하며 표기만으로 수신 성공을 추정하지 않는다.
- **프로그램 기본 원천은 검증된 통합 `_AL`**이다. 적격 종목의 해당 기준봉·세션은 `_AL`을 직접 요청하고 실제 응답을 검증해 사용한다. 유효한 `_AL`을 확보하지 못하면 `미검증/자료 부족`으로 처리하고 해당 범위의 계산·마킹을 차단한다. **`_NX`로 자동 우회·보완·대체하지 않는다.** `_AL` 실제 누락이 직접 수신증거로 확인되는 경우에도 `_NX` 사용은 별도 근거 검토와 사용자 승인이 있기 전까지 활성화하지 않는다. 시간대만으로 `_NX`를 선택하지 않는다.
- 위 우선순위는 **프로젝트 운영 계약**이다. 키움 공식 안내는 통합시세와 SOR 주문을 구분하고 통합 차트의 거래소 전환을 설명하지만, OpenAPI가 모든 시각·모든 기준봉에 `_AL` 봉을 반드시 제공한다는 뜻은 아니다. 불명확한 구간은 `미검증/자료 부족`으로 기록하고 허위 대체·차트 계산/마킹 허용을 하지 않는다.

- V5 전 기준봉: M1·M3·M5·M10·M15·M30·M60·M120·M240·D1·W1·MO1·Y1 (총 13개). 특정 M3만 점검하고 완료 처리하지 않는다.
- SOR 적격 종목의 과거 확정봉은 **해당 기준봉 네이티브 통합 원천 `_AL`을 먼저 직접 요청·검증**한다. 정규장뿐 아니라 장전·장후의 실제 `_AL` 수신봉도 증거가 유효하면 보존한다. SOR 미지원 종목은 확인된 KRX 전용 경로를 분리한다.
- 일·주·월·년봉은 키움 HTS의 동일 종목·날짜·수정주가 설정·기준봉·정규장 조건과 OHLCV가 일치해야 한다. `_AL`/직접 일봉 일부 일치가 확인되었다고 전 기간·전 기준봉 동일성을 단정하지 않는다.
- 장전·장후에 NXT 거래가 열린다는 사실은 `_NX` 단독시세로 전환할 근거가 아니다. 적격 종목은 해당 구간에도 **실제 검증된 `_AL`**을 사용한다. `_AL` 미수신·증거 부족 구간은 자료 부족으로 구분하며 `_NX`를 자동으로 끼워 넣지 않는다. `_AL` 봉의 존재를 추정해 만들거나 `_NX` 수신으로 과거 `_AL` 이력을 덮어쓰지 않는다.
- 기존 NXT 일·주·월·년봉 직접 수신 경로와 **현재 연도(2026) 연봉 유지** 계약은 보존한다. 단, NXT 전용 봉을 HTS 정규장 일·주·월·년봉에 임의 합산하지 않는다.
- V5의 '정규장만 표시'는 표시 봉뿐 아니라 지표·전체 필터·가상 BUY/SELL 재생의 계산 대상 세션도 함께 선택한다. ON이면 검증된 정규장 투영만 계산하고, 장외 봉을 숨긴 채 필터에 남기지 않는다. 원천 증빙을 바꾸거나 기간선택·마킹을 무력화하면 안 된다. 일·주·월·년의 HTS 정규장 기준봉을 자체 M1 필터/합산으로 만들지 않는다.
- **정규장 표시의 기간선택·마킹 증빙:** 기간선택은 네이티브 원본의 종목·시장·기준봉·조회·시각·완성·순서·OHLCV 증거를 유지하고, 표시 이력이 검증 원본의 정규장 투영과 정확히 일치해야 한다. 별도 마킹은 요청 표시봉이 검증된 전체 정규장 투영의 정확한 연속 접미 구간일 때 허용하며, 신호 재생에는 원본의 전체 정규장 투영을 사용하고 화면 범위만 잘라 표시한다.

## V5 정규장 계산 범위와 실매매 운영 분리

**상태 구분:** 아래 정규장 ON/OFF 및 위의 정규장 투영 증빙 항목은 현행 구현의 동작 기준이다. 옵션 축소와 제거 후 기본 범위는 최우선 작업연계의 검토·승인 대상이며, 문서 보강만으로 옵션을 삭제하거나 과거 정상화 작업을 자동 재개하지 않는다.

- **V5 독립 시뮬레이터:** 차트검증은 가상매매 참고자료이며 그 설정·지표·필터·마킹·가상손익은 실주문·계좌·포지션·실매매 루틴 상태 및 운영설정에 쓰거나 전파하지 않는다. 기존 공용 함수·원천의 재사용은 허용하되, V5 결과가 실매매의 신호·수익을 재현하거나 보장한다는 뜻은 아니다.
- **정규장만 표시 ON:** 해당 기준봉의 검증된 정규장 데이터만 차트에 표시하며, 모든 지표·필터와 가상 BUY/SELL 재생·마킹·가상손익은 **검증된 전체 정규장 투영**을 계산 입력으로 재산정한다. 장전·장후 봉은 화면에서만 숨기고 계산에 남겨두지 않는다. 화면 밖의 검증된 정규장 웜업 봉은 계속 사용하고, 미검증·부족분을 장외 봉으로 채우지 않는다. M5 15:35 네이티브 표시 전용 봉의 계산·웜업 제외 등 기존 예외를 유지한다.
- **정규장만 표시 OFF:** 종목·원천·세션 증빙이 유효한 기존 허용 전체장 데이터 범위를 사용하되, 기존 표시 전용 봉은 지표·필터·가상매매 입력에서 제외한다. 실제 존재하지 않는 시간대의 봉을 합성하지 않는다. ON/OFF 변경 시 선택된 입력 집합으로 지표·필터·가상 신호를 다시 계산하며, 기존 기간선택·마킹 초기화 및 독립성 계약을 보존한다.
- **관제창 실매매:** V5의 '정규장만 표시' 선택지는 실매매에 제공되지 않는다. 실매매의 캔들·지표·필터는 08:00~20:00 사이 **그 종목에 허용된 실제 거래 세션의 검증된 시세**를 사용한다. 이는 모든 종목의 전 시간대 거래·NXT 지원·연속 봉 생성을 뜻하지 않으며, 설정된 주문 운영시간으로 과거 지표 계산 입력을 잘라내지 않는다. 원천 우선순위·완성/형성봉·세션 경계 계약은 보존한다.
- **ATS·운영시간:** ATS 비적격 종목은 ATS 설정을 허용하지 않는다. 해당 종목의 **실제 유효 운영시간 = 종목별 거래 가능 시장 시간 ∩ 프로그램의 환경설정 ATS/시간운영 설정 시간**이다. 기존 AUTO_CLOSE·주문 권한·감시 및 안전 게이트의 별도 동작을 새로 정의하거나 폐기하지 않는다.
- **판정 경계:** 이 항목은 사용자 확정 정책이며 코드·실제 GUI·실수신 동작의 검증 완료를 의미하지 않는다. V5 독립 경계와 정규장 재생의 구현 정합성은 별도 확인 대상이다.

## 시장 세션(KST, 프로젝트 운영 계약)

**시장 거래시간과 시세 조회 원천은 별개**다. 이 표의 `NXT 장전/장후`는 거래가 열리는 시장을 가리키며 `_NX` 선택 근거가 아니다. 적격 종목은 모든 구간에서 **검증된 통합 `_AL`을 기본 원천으로 사용하고, 미확보 시 자료 부족으로 처리하며 `_NX` 자동 우회를 금지**한다. KRX 전용 종목과 종가 동시호가·마감 경계의 기존 확인 절차는 유지한다.

| 구간 | 거래 세션·경계 | 원천 확인과 처리 |
| --- | --- | --- |
| 08:00–08:50 | NXT 프리마켓 경쟁매매; 08:30부터 KRX 시가단일가 주문접수 병존 | **키움 통합호가의 실시간 시세 기준은 NXT**다. 이것만으로 OpenAPI `_AL` 직접 수신을 보장하지 않는다. 적격 종목은 해당 기준봉 `_AL`을 직접 요청·검증하며, 미확보 구간은 자료 부족으로 처리하고 `_NX`로 자동 우회하지 않는다 |
| 08:50–09:00 | NXT 프리마켓 휴장·KRX 시가단일가 주문접수·세션 경계 | **NXT 신규 체결봉은 없다.** KRX의 주문접수는 '거래소 전체 공백'과 구별한다. 실제 서버 체결·봉 없이 신규 봉을 합성하거나 NXT 형성값을 다음 세션으로 넘기지 않는다 |
| 09:00–15:20 | 정규 거래 | 적격 종목은 확인된 `_AL`, KRX-only는 확인된 KRX 직접 원천 |
| 15:20–15:30 | KRX 종가 동시호가 | 기존 마감 계약 유지; 실제 체결·서버 원천봉만 인정하고 임의 수신·보정 금지 |
| 15:30–15:40 | 마감 전환·희소 수신 | 기존 경계 계약 유지. 없는 분봉은 만들지 않고 검증된 M5 15:35 표시 전용 봉은 별도 취급 |
| 15:40–20:00 | NXT 장후 | 적격 종목은 해당 기준봉 `_AL`을 직접 확인한다. 미확보 구간은 자료 부족으로 구분하고 `_NX` 자동 보완은 적용하지 않는다 |

**원천 실증 경계:** 특정 과거 봉에서 `_AL`·`_NX`의 OHLCV가 일치해도 다른 시각·기준봉의 직접 TR 및 실시간 수신 가능성을 확장 추정하지 않는다. 실제 서버 체결이 없는 구간은 봉을 생성·복제·전방 채움하지 않는다.

키움 공식 기준: [대체거래소 도입 안내·통합호가 시간대별 제공기준](https://ocrw.kiwoom.com/pdf/guide/Kiwoom_Securities_Alternative_Exchange_Guide_Booklet_Double-Sided.pdf), [SOR 주문/통합·개별 시세 설정](https://download.kiwoom.com/hero4_help_new/9991.htm), [6600 통합키움차트](https://download.kiwoom.com/hero4_help_new/6600.htm), [조건검색 개발조건 도움말](https://download.kiwoom.com/hero4_help_doc/KiwoomHero4_AdvancedSearch.pdf). **HTS 통합호가의 시간대별 기준은 OpenAPI 개별 기준봉 `_AL`의 실수신 보장과 다르다.**

## V5 이력 수량 — 조회 요청·계산·표시를 구별

- 화면 표시 상한은 기준봉별 **5,000봉**이며, 지표·필터 계산용 숨김 웜업은 표시 수량에 포함하지 않는다.
- 기준봉별 기본 숨김 웜업은 **분봉(M1~M240) 900봉, 일봉(D1) 600봉, 주봉(W1) 300봉, 월봉(MO1)·년봉(Y1) 120봉**이다. 이는 기존 공용 지표 엔진의 기준봉별 이력 목표이며 모든 필터의 보편적인 최소 필요량이라고 단정하지 않는다.
- 실제 숨김 웜업은 `max(선택 기준봉의 기본 웜업, 설정된 지표·필터의 필요 이력)`으로 결정한다. 필요 이력이 기본값을 넘으면 **해당 기준봉에만** 추가 확보하고 다른 기준봉의 기본값을 일괄 상향하지 않는다.
- 지표 추가 필요량이 없는 기본 조회 목표는 **M1 6,000봉(표시 5,000 + 웜업 900 + 조회 여유 100), M3~M240 5,900봉, D1 5,600봉, W1 5,300봉, MO1·Y1 5,120봉**이다. M1의 100봉은 조회 안전 여유이며 계산 웜업 1,000봉을 뜻하지 않는다.
- **M5의 검증된 네이티브 15:35 봉**은 표시 전용으로 보존하고 계산·웜업에는 포함하지 않는다. 이로 인한 숨김 계산봉 부족분은 기존 해당 기준봉 네이티브 추가조회 경로로만 보정한다. 고정 수량을 전체 기준봉에 더하거나 과거 M1 재구성·출처 검증 우회를 하지 않는다.
- **서버 제공 수량만 사용:** 키움에서 실제 수신·검증한 해당 기준봉만 사용한다. 요청 목표·기본 웜업에 미달해도 가짜 봉·다른 기준봉 조립·외부 유료 데이터로 오래된 이력을 채우지 않는다. 직접 제공된 범위까지만 조회·표시하며 과거 구간을 임의로 연장하지 않는다.
- **짧은 이력의 13개 기준봉 공통 처리:** 유효한 직접 수신봉은 확보된 범위에서 최대 5,000봉까지 표시하고 기간선택·탐색을 유지한다. 지표·필터마다 필요한 최소 이력이 충족되는 봉부터 평가하며, 해당 BUY/SELL 신호·마킹은 관련 필터가 모두 준비된 구간에만 발행한다. 부족한 필터·구간은 자료 부족으로 표시하되, 그 이유만으로 차트 전체나 다른 준비된 필터를 차단하지 않는다. M240·Y1에도 동일 적용한다.
- **단순 부족과 원천 무효의 구별:** 단순 봉수 부족은 위와 같이 부분 사용한다. 종목·시장·세션·요청/응답 신원·OHLCV·완성 여부 등 원천 증빙이 불일치하는 범위는 기존 안전 차단을 유지한다. `_NX` 자동 우회·과거 M1 재구성·가상 캔들 생성 금지는 불변이다.
- V5에서 이전 캐시를 300봉짜리 부분 조회와 결합하여 새 수신 증빙을 전체 이력에 붙이는 경로는 사용하지 않는다. 증빙이 유효한 캐시는 유지하고 재조회가 필요하면 해당 기준봉의 전체 목표 수량을 네이티브 원천으로 요청·검증한다. 짧은 응답이 기존 캐시의 최신 확정봉·중복 행 전체와 일치하고 원천 증빙도 유효한 경우에만 해당 캐시를 재사용한다. 최신·변경 봉이 있으나 전체 이력이 부족하면 갱신 불완료를 표시하고, 선택 중인 종목의 검증된 캐시 파일은 유지한다.
- **V5 종목별 캐시 수명:** 선택 종목을 해제하면 해당 종목의 V5 전용 메모리·디스크 이력/표시 캐시를 모두 휘발하고 장기 누적하지 않는다. 늦게 도착한 응답으로 해제된 종목의 V5 캐시가 재생성되지 않게 한다. 다른 소비자의 공유 시세·운영 자료, 사용자 설정·실제 매매 기록, 복원점은 V5 전용 캐시 정리 대상이 아니다.
- **네이티브 증빙의 요청별 격리:** 기존 `VALIDATION_CACHE_RESTORE` 수신증거를 다른 요청 봉수의 확장 이력에 재사용하거나 가짜 `.market-source.json`을 생성하지 않는다. 선택 기준봉의 새 직접 TR 전체 응답이 확장 OHLCV를 검증하면 실제 요청 ID·원천시각·direct query를 채택한다. 일부·불일치 응답이면 검증된 캐시와 확보 가능한 필터 구간을 보존하고 미검증 범위의 계산을 안전 차단한다.
- **실매매·모의검증·간이차트의 완성봉 최소 300개 준비 계약**은 V5의 기준봉별 숨김 웜업과 별개다. V5 정정을 이유로 실매매·간이차트의 300봉 경로나 틱 기반 가격 판단을 변경하지 않는다.

## 당일 형성봉·실매매 공용 계약

**상태 구분:** 아래 V5 실시간 관찰·후속 틱 갱신은 축소 검토 전 현행 동작 기준이다. V5 틱 소비 제외 후 CURRENT 처리 정책은 미결정이며, 공용 수신·실매매 틱·직접 TR·원천 안전 규칙은 보존한다. 실시간 관찰 기능 유지를 새 작업의 확정 목표로 재해석하지 않는다.

- 과거 확정봉은 서버의 **해당 기준봉 직접 수신 OHLCV**만 사용한다. **V5의 현재 진행 중인 M3~M240 분봉은 2026-11-02 사용자 결정에 따라 선택 주기·동일 원천의 네이티브 CURRENT TR 스냅샷을 초기값으로 채택하고, 종목·원천·세션·수신순서·시각·거래량 연속성이 검증된 후속 체결 틱으로 OHLCV를 갱신한다.** 마켓 경계를 넘는 임의 봉 합성은 금지한다.
- **형성봉 접합 안전 조건:** TR 스냅샷과 첫 후속 틱의 포함 범위·누적 거래량 연결이 불명확하거나 이후 틱이 누락·중복되면 해당 형성봉의 지표·필터·신호 판단을 차단하고 **같은 원천·같은 선택 기준봉**에서 다시 직접 조회·검증한다. 재조회 자체를 누락·중복 해결의 증거로 간주하지 않으며, 확인 전 거래량·신호를 정상 판정하지 않는다. **M1 상위봉 재구성을 자동 대체/폴백으로 사용하지 않는다.**
- **이번 결정의 범위:** V5의 M3~M240 진행 분봉에 한정한다. M1 자체의 기존 처리, D1·W1·MO1·Y1 진행봉, 실매매·모의검증·간이차트의 별도 확정 동작을 이 문서 수정만으로 변경하거나 운영 일치·실창 PASS로 주장하지 않는다. 기존 틱 기반 BUY/SELL 가격 판단과 완료봉 직접 수신 계약은 유지한다.
- V5도 실시간 감시기이며 '마지막 1분봉 제외' 규칙은 폐기됐다. 실제 수신한 형성봉을 제외·완성 처리하는 임의 보정은 하지 않는다.
- 차트검증·모의검증·실매매는 동일 지표/필터 규칙을 사용한다. 실매매의 **매수·매도 가격 및 발생 판단은 모두 실시간 틱**에 따른다. 분봉 완성 대기 때문에 가격 판단을 늦추지 않는다.
- 관제 대상의 간이차트는 동일 확인 원천을 표시한다. 표시용 틱이 원천 확정봉·매매 신호·실제 주문 상태를 임의 변경하지 않는다.
- **V5와 실매매 주문 경계:** V5는 과거 가상매매와 실시간 관찰을 위한 화면으로 실제 주문을 직접 발송하지 않는다. 실제 BUY/SELL은 공용 필터·신호를 기존 루틴·소비자·주문 경로에서 처리하고 계좌·위험·안전 게이트를 보존한다. 테스트 중 실브로커 주문은 별도 사용자 명시 승인 없이는 금지한다.
- **운영·대기 원천과 간이차트:** 관제 등록 운영·대기 종목의 승인된 선택 기준봉 완성 이력은 `max(300봉, 선언된 루틴 이력 목표)`만큼 준비하고 실제 틱 감시를 유지한다. **WAITING 간이차트**에는 실제 서버 당일 봉만 표시하며 가짜 운영 시작·BUY/SELL 표식을 만들지 않는다. **ONGOING 간이차트**는 실제 시작~종료 매매 기간과 기존 매수·매도 마커를 보존한다.

## V5 미완료 기능과 정리 대상

- 기준봉 13개 전환·재진입·로딩과 지표 필터·기간선택 결과/해제를 보존한다. 독립 마킹의 기간선택 대체 방향 및 정규장 옵션·V5 틱 축소안의 승인 상태는 최우선 작업연계를 따른다. 과거 독립 ON/OFF 공존을 새 구현 목표로 되살리거나 일부 성공으로 V5 완료를 선언하지 않는다.
- 기준봉/원천/세션 전환 중 마킹·기간선택은 리셋 또는 바인딩 완료 후 안전하게 재개해야 한다. 계산봉과 표시봉의 바인딩 불일치로 무작정 영구 차단하지 않는다.
- **정규장만 표시 전환의 뷰포트 안정성:** ON/OFF 전환 시 사용자가 보던 중심 시각과 기존 수직 이동·확대 의도를 유효한 표시 범위 안에서 유지하고, 갱신된 봉의 가격이 화면 위아래로 잘리지 않도록 가격축을 복원·재산정한다. 로딩 실패·취소가 이전 화면의 축과 중심 상태를 오염시키지 않게 한다. 전환 시 마킹·기간선택 초기화 계약은 유지한다.
- **기간선택 방식:** 시작점을 **더블클릭**하고 **오른쪽으로 드래그한 뒤 왼쪽 마우스 버튼을 놓으면 종료**한다. 범위 해제와 차트의 다른 조작은 유지하며, 선택 결과 실행을 폐지 대상인 독립 마킹 ON/OFF에 종속시키지 않는다.
- **기간선택 계산·마킹 — 최신 대체 방향:** 선택 구간 안에서 이전 보유수량 이월(carry-in) 없이 BUY/SELL 가상매매를 재생하고 결과표·평단·손익·승인된 가상청산을 표시한다. 선택 해제 시 가상 결과·표식만 지우고 캔들·지표·필터는 유지한다. 독립 마킹 OFF 조작이나 선택 해제 후 전체 범위 가상 마킹 복원은 새 구현 요구가 아니다. 문서 확정 방향과 실제 구현 완료는 구별한다.
- **V5 탐색:** 준비된 표시 이력은 최대 5,000봉이며 휠은 최대 3,500봉 표시까지 비례 확대·축소하고 그 이후 적재된 과거봉 안에서 수평 탐색한다. 5,000봉 적재가 완료된 뒤 휠·슬라이더 조작만으로 이력 TR을 추가 요청하지 않는다. 기존 스크롤 핸들과 끝점 동작을 보존한다.
- **차트 조작 보존:** 기존 수평 팬·수평 줌·수직 이동은 유지한다. 독립 마킹 ON/OFF 존속을 전제로 한 팬·줌 시 OFF 규칙은 기간선택 대체 후의 신규 구현 요구에서 제외한다. 이것만으로 기간선택의 팬·줌·해제 동작을 새로 정의하거나 변경하지 않는다.
- **필터·범례 표시:** VALID는 유효 필터를 강조한다. 별개로 범례에서 특정 필터 신원을 클릭하면 그 필터를 강조하고 다른 필터의 가격 표시·지표 창을 함께 숨긴다. NOT 빨강·내부 NOT 노랑, RSI 70/30 기준선, 기존 매수·매도 마커와 툴팁을 보존한다.
- **기간선택 가상 청산:** 독립된 `청산` 체크박스는 기본 OFF이고 실제 주문과 분리한다. ON에서 선택 종료봉의 유효한 양수 종가로 남은 보유수량만 전량 가상 SELL하며, 이미 전량 매도됐거나 무보유면 중복 청산하지 않는다. 기존 가상매도 거래비용과 손익 산정 규칙을 동일 적용한다. OFF일 때 기존 완성 매매사이클·손익 요약·평단선은 불변이며, OFF·기간선택 해제 시 가상 청산 행·마킹은 표시하지 않는다.
- **V5 단일 운영·호환 자료 보호:** 운영 진입은 V5 하나로 유지한다. 버전 이름이 오래된 사용자 설정 키·공용 시세/운영 캐시·공통 테스트 자료는 현행 사용·읽기 호환·안전 이전을 확인하기 전 임의 삭제·이동하지 않는다. 종목 해제 시 V5 전용 캐시 휘발은 위 보호 자료와 구분하여 적용한다.
- 기간선택 시작·종료 시각 표기, 종료 세로선에서 가상 '청산' 매도 마킹, 체크박스 구분자 `|` 좌우 간격은 기존 요청으로 유지한다.
- 실제 서버 수신 없는 캔들 보충, 과거 M1을 통한 상위봉 재조합·검증, 근거 없는 MA600 강제, 형성 중 M1 임의 제외, 증빙된 `_AL` 이력의 `_NX` 일괄 교체를 금지한다.
